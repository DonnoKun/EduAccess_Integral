# Architecture rules
- Use the full-resolution logo import for loading screens and derive favicon/PWA sizes from that same source; enlarging a favicon blurs the brand.
- Await local auth sign-out and preview storage removal before the shared logout redirect; early reloads resurrect persisted sessions for either role.
- Group lesson edits are stored in owner-only lesson_drafts; publishing copies a draft into group_lessons so students never see unfinished edits.
- Pin each student's first published lesson snapshot in lesson_progress and preserve it on updates; exercise answers and scores must remain tied to the material they started.
- Await device voice readiness through shared browser speech selection for setup, tutorials and lessons so both roles prefer the same natural language-matched voices without paid AI calls.
- Draw setup media samples in code (SVG + CSS animation) so they show on every host and device without file downloads or AI content per user.
- Onboarding owns global preview styles until unmount, then restores the saved profile; background profile application must not overwrite an active preview.
- Show saved exercise-based lesson progress separately from each audio block's playback percentage, preserving explicit completion on revisit.
- Translate original structured lesson content rather than regenerating a topic; validate structure and preserve source URLs and image prompts to prevent changed exercises and unnecessary image generation.
- Manual lesson players remain available independently of automatic TTS preference; shared Button markers scale control dimensions and icons with profile text across roles.- Teacher-written short texts (group/lesson descriptions) are translated once per language via the generate-course-content `texts` mode and stored in the shared AI cache, so viewing never re-spends credits.
- Profile CSS inside Tailwind @layer must target third-party classes via attribute selectors (e.g. svg[class~="lucide"]); class selectors not present in src are purged.
- Shared form and dialog markers own accessible dimensions; headers use stable grid rows and search uses font-aware minimum tracks to avoid language-dependent overlap.
- Vercel deploys need vercel.json SPA rewrites to index.html so every deep link (/dashboard, /courses, /courses/:id/lessons/:id...) loads instead of 404, with a catch-all last and static paths rewritten to themselves; rewrite sources must stay in plain path-to-regexp syntax (`/(.*)`, `:name*`) because Vercel's matcher silently rejects lookahead groups like `((?!...)`, which leaves deep links 404ing.
- Every AI edge call goes through supabase/functions/_shared/ai-gateway.ts (timeout, retry, Postgres circuit breaker, secondary model, cache, one resilience_metrics row per call); new AI endpoints wrap aiEndpoint() for auth, rate limit, zod and strict CORS so resilience is measurable for the thesis.
- Thesis service map S1-S5 = content-aggregation, visual-profiling, accessibility-remediation(+microservices), ai-orchestration (cron worker), content-delivery; new services stay thin wrappers over aiEndpoint/resilientChat.
- Benchmark fault injection/baseline flags (BenchOptions) are only constructed in code by the cron-auth protected resilience-benchmark runner, which uses an isolated bench:* breaker; never parse them from request bodies so public AI endpoints cannot reach them.
- Benchmark batches checkpoint calls and phases under a database lease; aggregate only completed stored repetitions with Student-t intervals, and pause uncertain in-flight calls instead of replaying potentially billed inference.

- Concurrency sweeps use immutable parents, stored-phase/call completion checks and idempotent metric writes; explicitly authorized incomplete-cell restarts clean only that exact cell under a lease, while completed cells are never replayed to avoid rebilling.
- Content-quality signals are additive lesson JSON, backed by cached control topics and advisory review; mark edited signals stale and regenerate only the selected draft section so publication and student snapshots remain isolated.
- Search and group lesson pages share LessonReader and LessonToolbar; loaders and progress persistence remain separate to preserve pinned student snapshots.
- Search lesson cache identity includes resource, format, level and language; direct searches generate only the selected version and omit advisory inference intended for teacher review.
- Opened search lessons use existing user_library rows with content_data pin/open metadata; retain saved/completed status so analytics and existing policies stay compatible.
- Image descriptions use actual multimodal image input and versioned caches; refuse metadata-only descriptions rather than invent visual evidence.
- Normalize the complete image-generation prompt to English through the cached resilient gateway after bitmap lookup, so automatic and manual callers share one boundary.
- Teacher lesson reuse copies owned content into a new unpublished row; never reuse the original identifier or trigger inference.
- Long lesson generation opts into a longer bounded gateway timeout with no retries and a compatible secondary tool request; default service and benchmark policies remain unchanged.
- Every user-visible change bumps the app version (settings.about.version in es/en locales and package.json) in the same commit so About always shows the current release.
- Only educational topics may produce search results or lessons; a cached shared topic guard (_shared/topic-guard.ts) checks new topics server-side so every client and role is covered.
